I'm adaptive by default — drop me into a stack I've never touched and I'll figure out how to ship in it. My work isn't built around one language or one role; it's built around the habit of turning unfamiliar, messy, real-world problems into systems that actually work in production.

## 🧭 Domains I've Worked Across

- **Telecom & ISP operations** — multi-tenant operator/HQ dashboards, customer accounts at scale, recharge and billing pipelines, wallet and financial-split logic, IVR + call-recording integrations.
- **Travel-tech & fintech backends** — Django microservices for eSIM provisioning, payments, multi-currency wallets, scraping and exchange-rate pipelines, containerised deployments on Docker Swarm.
- **Autonomous drones & robotics** — ROS 2 multi-drone systems on ArduPilot + MAVLink, KML-to-mission waypoint planning, SITL and hardware-in-the-loop testing, direct drone-to-drone telemetry for autonomous survey + spray coordination.
- **Geospatial & remote-sensing ML** — fusing Sentinel-1 SAR, Sentinel-2 optical, SRTM terrain, ESA WorldCover, and weather/soil APIs through XGBoost for agricultural land-use verification.
- **Edge AI & embedded systems** — ESP32-S3 with TinyML for on-device gesture recognition, OLED + speech I/O hardware for assistive tech, offline-first device firmware.
- **Computer vision in the field** — OpenCV pipelines running on-board UAVs, geotagging detections against live MAVLink GPS telemetry.
- **Full-stack web & mobile** — React / Next.js / Vite + Supabase / Postgres SaaS products, Flutter mobile apps, Tauri + Rust desktop, design-system-driven landing pages and admin dashboards.
- **Internal tooling & community platforms** — identity & ID-card systems, inventory management, content/CMS-driven sites, accessibility-first interfaces.

## 🛠 How I Work

I bias toward *the smallest thing that proves the system works*, then I harden where it actually hurts. I read docs, write them, set up the infra, and treat developer experience as part of the deliverable. I've shipped in Python, TypeScript, Dart, Rust, C / C++, and Lua — but the through-line is the same: if there's no template for the problem, I'll build the template.

## 🤝 Community

I stay active in the maker and engineering community around me — organizing and speaking at events like **Raspberry Pi Jam** and **Arduino Day**, running hands-on workshops (most recently a Flutter session for 100+ students), mentoring teams at hackathons like the **Physical AI Hackathon** (MakerGram × TinkerHub × Google), and helping keep makerspace and student-chapter infrastructure running at TinkerSpace and CUSAT.
